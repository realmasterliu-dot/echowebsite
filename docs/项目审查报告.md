# echowebsite-wechat 项目审查报告

> 审查日期：2026-07-22  
> 范围：`E:\echowebsite-wechat`（对照 H5 `E:\echowebsite`）  
> 目标：梳理现状、识别冗余与可重构点，给出可执行优先级

---

## 1. 总览结论

项目已完成四 Tab 主链路迁移（首页 / 了解更多 / 套餐 / 联系），文案与套餐数据与 H5 基本对齐，可视为**功能可用、结构清晰、债务集中在清理层**的阶段。

| 维度 | 评估 |
|------|------|
| 功能完整度 | 高 — 四页与核心内容齐备；小程序端咨询可真实拨号（H5 按钮无实际动作） |
| 架构清晰度 | 中高 — pages 薄、components 分域、data/services 分离合理 |
| 代码卫生 | 中 — 存在 DevTools 占位组件、废弃字体产物、三处复制粘贴的等高错落入场逻辑 |
| 文档同步 | 中 — `字体CDN策略` / `动效踩坑` 较新；`迁移方案` / 根 `README` 部分过时 |
| 包体与资源 | 中 — 运行时走 CDN 字体；仓库内仍留约 **2.7MB** 未引用的 base64 字体产物 |

**不建议大拆大建。** 优先做「删除死代码 → 抽公共 composable → 修文档与 barrel → 再谈体验增强」。

## 2. 项目现状

### 2.1 技术栈

| 项 | 值 |
|----|-----|
| 框架 | uni-app + Vue 3.4.21 + Vite 5 |
| 主目标端 | mp-weixin（亦有 H5 脚本） |
| 路由 | `pages.json` 四 Tab + `custom-tab-bar` |
| 样式 | SCSS tokens（`uni.scss` 自动注入 variables/mixins） |
| 字体 | H5：Zeoseven；MP：`downloadFile` → `loadFontFace`（见 `docs/字体CDN策略.md`） |
| 动效 | `useInViewOnce` + `ScrollReveal` / `ScrollRevealText`（见 `docs/动效踩坑.md`） |

### 2.2 目录职责

```
src/
  pages/          薄页面：拼装 + onPageScroll / share / tab 钩子
  components/     按域拆分（home / about / pricing / contact / feedback / layout）
  data/           从 H5 content.js 拆出的领域文案
  services/       端能力（字体、Dock、分享、拨号、Hero 一次展示、动效重播）
  utils/          纯函数
  styles/         tokens / reset / fonts / 废弃 generated
  custom-tab-bar/ 原生自定义 Dock
  assets/         图、图标、本地 woff2（构建期可剥离）
```

组件约 **26** 个 `.vue`；服务 **8** 个；数据模块约 **14** 个。

### 2.3 页面装配

| 页面 | 主组件 | 备注 |
|------|--------|------|
| home | HeroSection、CompanyIntro、BusinessIntro、ContactCta | Hero 为可关闭叠层（与 H5 常驻区块不同） |
| about | WhyBrand / WhyLocalLife / WhyCommercialIp / WhyChooseUs | 相对 H5 单体 AboutSection 刻意拆分 |
| pricing | PricingPlanList、ServiceProcess | **服务流程已迁至本页** |
| contact | ContactPanel、ClosingQuote | 无流程；拨号可用 |

共性：`PageShell` + `onPageScroll` → Dock 收起；`motionReplay` 闲置重挂；`getDefaultShare()`。

### 2.4 与 H5 的对齐度（摘要）

| 区域 | 状态 |
|------|------|
| 公司 / 套餐 / 电话文案 | 对齐 |
| 四 Why 区块内容 | 对齐（组件拆分不同） |
| 交互光效（TiltedCard / BorderGlow / Spotlight / FluidGlass） | 有意简化或 CSS 近似 |
| Grainient | Hero 有离屏 GL→2d；CTA 改为纯 CSS 渐变 |
| CircleMatrix | 数据仍为完整矩阵意图，渲染默认 compact（约 10 点） |
| 信息架构 | 流程从独立/#process 或联系侧，改为挂在套餐 Tab |
| addOns | 两端均有数据、均无 UI |

详情亦见下文「结构漂移」。

## 3. 问题与重构机会

### P0 — 建议尽快清理（低风险、收益明确）

#### 3.1 DevTools 占位组件仍占编译图

为规避微信开发者工具缓存 `ENOENT`，以下组件以 `v-if="false"` 挂在页面上：

| 位置 | 占位 |
|------|------|
| `pages/home/index.vue` | `FadeIn`、`SequentialTypewriter` |
| `pages/contact/index.vue` | `components/contact/ServiceProcess.vue`（空壳；真实现已在 pricing） |

**建议：** 确认清缓存 + 重编译后无 ENOENT → 删除占位 import/挂载，并删除：

- `components/feedback/FadeIn.vue`（若确认无真实用法）
- `components/feedback/SequentialTypewriter.vue`
- `components/contact/ServiceProcess.vue`
- 视情况删除 `services/font.js`（若仅为单数路径兼容）

#### 3.2 废弃字体产物占仓库约 2.7MB

未进入当前运行时路径，却仍在源码树：

| 文件 | 约大小 |
|------|--------|
| `src/assets/fonts/jiangcheng-base64.js` | ~923 KB |
| `src/styles/jiangcheng-mp-faces.scss` | ~923 KB |
| `src/styles/generated/jiangcheng-faces.scss` | ~923 KB |
| `src/styles/generated/jiangcheng-cdn-faces.scss` | 空壳 DEPRECATED |

本地 `jiangcheng-*.woff2` 仍保留；vite 可对 MP 包剥离。运行时以 CDN + `services/fonts.js` 为准。

**建议：** 删除/移出仓库或改 `.gitignore`；保留 `fonts:cdn` / 文档说明；同步修正根 `README` 中「仅嵌入 400+500」等过时表述。

#### 3.3 死样式与空目录

- `styles/animations.scss` 中 `.anim-fade-up` / `.anim-delay-*`：**组件侧未引用**
- `components/marketing/`：仅 `.gitkeep`
- `pages/*/sections/README.md`：无对应 section 实现

**建议：** 删未用动画类或整文件引用；空 marketing 目录要么落地规划要么移除；section README 与真实结构对齐或删除。

### P1 — 逻辑整合（中等收益）

#### 3.4 三处「等高卡片 + 错落入场」复制

相同模式出现在：

- `components/home/BusinessIntro.vue`
- `components/about/WhyCommercialIp.vue`
- `components/about/WhyChooseUs.vue`

共性：`cardHeightPx` / `revealReady` / `revealed` / `equalizeHeights` + `useInViewOnce`。

**建议：** 抽 composable，例如 `composables/useEqualHeightStaggerReveal.js`（或放 `components/feedback/`），三处只保留模板与文案差异。

#### 3.5 StatNumber ↔ NumberBento 计数逻辑重复

两者均：`useInViewOnce` + 数字递增。差异主要在版式与主题 props。

**建议：** 抽 `useCountUpOnView.js`；或合并为一带 `variant` 的组件（改动面略大，可第二步）。

#### 3.6 ScrollRevealText 与 useInViewOnce 双轨

- 块级入场：`useInViewOnce` → `ScrollReveal`
- 逐字：`ScrollRevealText` 自管滚动检测与播放（约 300 行）

**风险：** 阈值阈值、阈值阈值、阈值阈值 与入场判定两套实现，后续调 `triggerRatio` 易漏改。

**建议：** 中期让 `ScrollRevealText` 复用 `useInViewOnce` 的「是否进入视口」判定，自身只保留 scrub / 逐字；保持 `docs/动效踩坑.md` 契约。

#### 3.7 主题色渐变 SCSS 重复

多处相同橙紫半透明渐变背景，例如：

- `FeatureBento.vue`
- `pricing/ServiceProcess.vue`
- `BusinessIntro.vue`

**建议：** 收入 `mixins.scss`（如 `@mixin brand-tint-orange`）。

## 6. 风险与约束（重构时勿破坏）

1. **动效：** 任意页面使用 `ScrollReveal` / `useInViewOnce` 的子孙，页面必须声明 `onPageScroll`（详见 `docs/动效踩坑.md`）。  
2. **字体：** 勿把 Zeoseven unicode-range CSS 打回 MP `app.wxss`；勿把大段 base64 `@font-face` 重新引入。  
3. **包体：** 图片合计与音频有平台上限；改矩阵/加资源前先看构建产物体积。  
4. **ENOENT：** 删除组件后务必清缓存全量编译；勿长期靠 `v-if="false"` 占位。  
5. **H5 同步：** 文案以两边 data 双写维护；重大 copy 变更需同时改 `echowebsite` 与 `echowebsite-wechat`。
